## 1. 배경

- 고객(화장품 브랜드 등)이 **상품(제품)마다 견적서를 요청**하는 운영이 반복된다
- 현재는 고객 정보 없이도 견적서가 작성되어 이력에 남는다 → "어떤 고객 대상 견적인지" 알 수 없는 레코드가 쌓임
- SKU 제품명이 미입력 시 `充填物1`로 자동 치환되어, **상품 이름이 견적서에 안 나가는 경우**가 있음
- 반면 원가 시뮬레이터는 "계산기처럼" 조건만 바꿔 가격을 살펴보는 용도으로도 쓰인다 → **시뮬레이터는 자유롭게, 발행 시점에만 강제**해야 함

## 2. 핵심 개념: 「계산」과 「발행」의 분리

```
원가 시뮬레이터 (/)            견적서 페이지 (/quote)              이력 (/history)
┌────────────────┐   진행   ┌────────────────────┐   발행   ┌──────────────┐
│ 조건 입력·계산    │ ──────→ │ 고객 정보 입력(이동)  │ ──────→ │ PDF 출력       │
│ (계산기 모드 OK)  │         │ 견적서 편집·A4 미리보기│         │ 메일 작성      │
│ 고객 정보 UI 제거  │         │ 필수 정보 검증        │         │ 상태 관리      │
└────────────────┘         └────────────────────┘         └──────────────┘
```

- **시뮬레이터**: 견적 확정 의사 없이 자유롭게 계산 가능 (제품명 미입력·고객 미입력 허용)
- **발행**: 세금·금액·고객·제품명이 확정된 공식 견적서로, 이력에 영구 보존

## 3. 화면별 변경 사항

### 3.1 원가 시뮬레이터 (`/`)

| 변경 | 내용 |
|---|---|
| **고객 정보 패널 제거** | 「顧客情報」섹션(고객코드·마스터 검색·저장·일람)을 `/quote`로 이동. 시뮬레이터는 제품 조건과 계산에 집중 |
| 「見積書発行へ進む」유지 | 버튼 클릭 시 **사전 검증**: SKU 제품명 미입력이 있으면 /quote 진입을 차단하고 입력 요청 (진행 의사가 있으므로 이 시점에 검증) |
| 제품명 플레이스홀더 유지 | 시뮬레이터 내 계산에는 `充填物N` 기본값 사용 가능 (계산기 모드 보장) |

### 3.2 견적서 페이지 (`/quote`)

| 변경 | 내용 |
|---|---|
| **고객 정보 섹션 신설** | 상단(또는 좌측 패널 상단)에 「顧客情報」블록: 고객코드 입력 → 마스터 자동 읽기 → 미등록 시 신규 저장. 회사명·담당자·우편번호·주소·전화·이메일 입력란 |
| **「履歴に保存」→「見積書を発行」** | 버튼명·모바일 하단 버튼 일괄 변경. 발행 개념으로 통일 |
| **발행 필수 검증** | 하기 4장 참조. 미충족 시 발행 버튼 비활성 + 부족 항목 안내 |
| SKU 제품명 | 사양 섹션의 SKU 표시에 제품명 반영(이미 반영됨). 발행 시 전 SKU 입력 확인 |
| A4 미리보기 | 기존 A4 시트 그대로 (UI 내 미리보기 기능은 이미 충족, 유지·개선) |
| 발행 완료 안내 | "견적서를 발행했습니다 → 이력에서 PDF 출력·메일 발송이 가능합니다" + 이력으로 이동 버튼 |

### 3.3 견적 이력 (`/history`)

| 변경 | 내용 |
|---|---|
| **PDF 출력 버튼** | 목록 카드 및 상세 화면에 「PDF出力(A4)」버튼 → 브라우저 인쇄(PDF 저장) 호출 (기존 A4 고정 출력 활용) |
| **메일 작성 버튼** | 「メール作成」→ mailto 링크로 메일 앱 자동 작성 (수신자=고객 이메일, 제목=見積書番号, 본문=금액 요약) ※첨부는 수동 |
| 상태 연동 | 메일 작성 완료 시 상태를 `sent`로 변경하는 버튼 제공 |
| 고객 미입력 구 레코드 | 기존 데이터는 수정하지 않고 「得意先未入力」배지 표시 |

## 4. 발행 필수 입력 검증 규칙 (안)

| # | 항목 | 필수 시점 | 비고 |
|---|---|---|---|
| 1 | 会社名(得意先名) | **발행** | 공백 불가. 마스터 읽기 또는 수동 입력 |
| 2 | SKU별 제품명(全SKU) | **/quote 진입 + 발행** | `充填物N` 자동 채움은 시뮬레이터 계산에만 허용 |
| 3 | 원가 연동 상태 | 발행 | 기존 stale 검증 유지 (시뮬레이터 조건 변경 시 재계산 필요) |
| 4 | 見積番号·발행일·유효기한 | 발행 | 자동 생성값 확인 (형식 S7-YYYYMM-001) |
| 5 | 고객 이메일 | **메일 발송 시** | 발행 자체에는 불필요, mailto 시 형식 검증 |

- 검증은 **UI(버튼 비활성+안내)와 API(서버 재검증) 이중**으로 구현
- 고객 마스터 저장 규칙(고객코드+회사명 필요)은 기존 유지

## 5. PDF·미리보기·메일 전략

| 단계 | 방식 | 설명 |
|---|---|---|
| Phase 1 | 브라우저 인쇄 PDF | 기존 「PDF出力(A4)」= window.print. 이력에도 동일 버튼 추가. 별도 서버 비용 없음 |
| Phase 1 | mailto 메일 작성 | 제목: `お見積書 {番号} のご案内`, 본문: 제품명·수량·세액합계·유효기한. PDF 첨부는 수동 |
| Phase 3 | **XSERVER SMTP 자동 발송** | 발신: `shaepouch@package-lab.com`. SMTP 자격증명 확보 후 착수 (Critic 조건: 자격증명 전 구현 금지) |

## 6. 데이터·상태 변경

- DB 스키마 변경 **없음** (고객 필드는 quotations 테이블에 이미 존재)
- API `validateQuotationInput`에 발행 검증 추가 (회사명·SKU명)
- 상태 흐름 유지: `draft(발행) → sent(메일 발송) → approved / rejected / expired`
- 시뮬레이터 초안(draft)에는 고객 정보를 담지 않고 /quote에서 입력 (기존 sessionStorage 전달 구조 단순화)

## 7. 구현 단계

| Phase | 내용 | 예상 규모 |
|---|---|---|
| **1** | 고객 UI 이동(/quote), 발행 버튼 개명+필수 검증(UI·API), SKU 제품명 발행 검증, 이력 PDF 출력·mailto·sent 처리, 구 레코드 배지 | 중 (견적 페이지 중심 리팩터링) |
| **2** | **필름 단가 마스터**(관리 페이지·DB·API, 유효기간 1개월·변경이력) + 계산 연동 + 발행 시점 가격 고정 | 중 |
| **3** | XSERVER SMTP 자동 발송 (shaepouch@package-lab.com, 자격증명 확보 후) | 대 (외부 의존·자격증명) |

각 Phase 완료 시: 전체 테스트 + 수동 시나리오 검증(시뮬레이터 자유 계산 → 진입 검증 → 발행 검증 → 이력 PDF → 메일 작성)

## 9. 확정 사항 (2026-10-09 사용자 확인)

1. 필수: **회사명·우편번호·전화번호·주소** / 선택: 담당자(個人)·이메일
2. SKU 제품명 검증은 **견적서 발행 시점에 발동** (시뮬레이터→/quote 진입은 자유)
3. 메일: **XSERVER SMTP 사용, 발신 shaepouch@package-lab.com** — Phase 3(자격증명 확보 후), 우선 mailto
4. 필름 가격 유효기간: **1개월** (견적 유효기간 30일과 정렬)
5. 재발행: **1개월마다 갱신 재발행** 운영 (동일 번호 upsert 유지)
6. 구 고객 미입력 이력: 데이터 수정 없이 「得意先未入力」배지 표시 (기본안)
